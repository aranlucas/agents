# Planned user outcomes

Proposed sequence from October 26, 2026; these are acceptance goals, not shipped behavior or delivery dates.

1. **Bounded work.** Expose the requested outcome, workflow, current step, and user-selected work budget. Stop scheduling at the limit and return completed work, uncertainty, and a resumable next action. Separate provider-reported usage from estimates.
2. **Safe resumption.** Restore the same run and domain result after interruption. A reconnect must not start the job twice or automatically replay a mutation whose outcome is uncertain.
3. **Reusable results.** Start with one grocery or travel journey: preserve sources, unresolved choices, and explicit approval before external changes. Mobile and MCP clients should share result identity and revisions; edits must survive returning to chat.

Measure useful completion, provider usage, elapsed time, repeated tool calls, and interventions on bounded grocery/travel tasks before expanding the catalog. Collect voluntary feedback and aggregate operational events without private content, credentials, or account identifiers. Prioritize predictable completion and recovery over more specialists or broader autonomous writes.
